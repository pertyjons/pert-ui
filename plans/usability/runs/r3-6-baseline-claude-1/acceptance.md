### 2. Typing, marker, counts, Ctrl+S, menu Save, failed save: met

- Code: the tab title shows `name *` when `text != saved` (src/lib.rs:124).
  The status line comes from `status_line` through a `Dynamic` label
  (src/lib.rs:71-75, 376-384). Save is one registered command bound to
  `KeyChord::primary('s')` and used by the menu item via
  `MenuItem::command` (src/lib.rs:306-316, 341). On a write error,
  `save_note` calls `notify` and leaves `saved` unchanged, so the marker
  stays (src/lib.rs:186-200). The notification is a `Banner`
  (src/lib.rs:387-391).
- Notification under the frozen interpretation: the failure is shown in a
  `Banner`, not a `ToastStack`. The rules accept "a visible failure message
  in another component … if inspection exposes it". The 0.3.75 `Banner`
  reports `SemanticRole::Alert` with the message as its name and
  `expanded = shown`. After the failed save, inspection showed
  `(Alert, "Could not save kiwi.txt: No such file or directory (os error 2)", expanded true)`
  (`evidence/03-full-suite.log`), and there was no such component before the
  failure. `acceptance-failed-save.png` shows the banner with the real OS
  error and the tab `apple.txt *`. The message is the actual `io::Error`
  (src/lib.rs:196).
- Tester check: `typing_marks_modified_and_saving_clears_it`
  (tests/notes.rs:230). It covers typed text with `\n`, the marker and counts
  from inspection, Ctrl+S and File→Save with disk compares, and a failed save
  that shows the message and keeps the marker. Its menu Save is driven by
  F10, arrow keys and Enter, not by a click.
- Author check: `item2_typing_saving_and_failed_save` (tests/acceptance.rs:310).
  - Typing goes into the `TextArea` after a pointer click. It includes a line
    break from the Enter key and a `\n` inside typed text. The editor's
    inspected value is `"first line\nsecond  line\nthird"`. The status reads
    `kiwi.txt: 3 lines, 5 words`, and the marker appears on that tab only.
  - Ctrl+S writes exactly that text to disk, and the marker clears.
  - A **clicked** File→Save writes the new four-line text, and the marker
    clears. The untouched note stays the same on disk.
  - After the folder is removed, Ctrl+S produces the Alert notification
    above and the marker stays.
  - Dismiss hides the notification. A second failure through the clicked
    File→Save shows it again and the marker stays.
- `item2_failed_save_capture` (tests/acceptance.rs:575) provides the
  corroborating capture. Passes.

### 4. Close choices and the unmodified close: met

- Code: Close tab is one command bound to Ctrl+W and to the menu item
  (src/lib.rs:318-332, 342). It closes an unmodified tab directly and opens
  `close_dialog` for a modified tab. The handlers are at src/lib.rs:430-472:
  - Save calls `save_note` and closes only when the save succeeded.
  - Discard calls `close_tab` without writing.
  - Cancel keeps the tab.
- Tester check: `closing_tabs` (tests/notes.rs:317). It covers Cancel,
  Escape, Discard, Save, an unmodified close (checking that `close-form` is
  not visible), and a failed Save that keeps the tab.
- Author check: `item4_close_choices` (tests/acceptance.rs:462).
  - **Cancel** (Ctrl+W): the dialog opens, and its message is visible in
    inspection. Afterwards the tab and its `*` marker remain, the editor
    value still has the edit, and the disk file is unchanged.
  - **Discard** (clicked File→Close tab): the tab is removed and the disk
    file is unchanged.
  - **Save** (Ctrl+W): the disk file equals the editor text and the tab is
    removed. The handler writes before closing and closes only on success
    (src/lib.rs:442-444). The failed-save case below confirms that a failed
    write keeps the tab.
  - **Unmodified tab**, by Ctrl+W and by the clicked menu item: it closes at
    once, and the snapshot has zero open Dialog or AlertDialog components.
  - **Failed Save in the dialog** (folder removed): the tab stays with its
    marker and a notification is shown. Passes.
