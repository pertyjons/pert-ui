## Merged findings

- **M1, the getting-started dependency** (r1-1-claude#1, r1-1-codex#1, r1-2-claude#1, r1-2-codex#1, r1-3-claude#1, r1-4-claude#1, pilot-2-claude#1, pilot-2-codex#1). 8 entries from 8 of the 10 runs. The guide is correct now and becomes wrong at the first registry release. Only getting-started.md:9-19 needs to change: the other `cargo run -p` lines are already labelled "from a checkout". The guide is also inconsistent with itself, because appearance.md:504 and diagnostics.md:174 already write `pert-ui = { version = "…", … }`.
  - **Serving both:** lead with the registry form, using the same `version = "…"` placeholder or the real version kept in step by a test as `tests/foundation/readme.rs` does for status.md. Follow it with "Before the first registry release, or to follow unreleased changes, depend on a checkout instead: `path = …`".
  - Name the MSRV from status.md ("Requires Rust 1.99.1 or later") instead of `rust-toolchain.toml`, which a registry user does not have.
  - Note that the examples ship in the package (`include` has `/examples/**`, crates/pert-ui/Cargo.toml:13) and that `cargo run -p` needs a checkout.
  - For round 2, either land this or have the tester brief say that the kit stands in for a release.
- **M2, runtime-crate examples on facade pages** (r1-4-claude#2, pilot-2-claude#4; also pilot-2-claude's closing wish 3 and r1-4-claude's acceptance notes). 276 of 310 example blocks at the crate root. The fix is the hidden crate alias.
- **M3, the prelude lacks the shortcut types** (r1-2-claude#7, pilot-2-claude#5, pilot-2-codex#2, r1-2-codex#2's imports). `Modifiers`, `KeyChord`, `CommandKey` and `CommandScope` were imported from the root by 6 to 8 of the 10 tester code bases, and `CommandScope`/`KeyChord` also by the maintainer's own task-4 app. The rule's "keyboard … types an application configures" predicts their membership. Slice 9's inputs already list `CommandScope` and `KeyChord` from the mixer probe (plans/app-author-improvements.md:370-374). This merges with U1, since rustc does not point to the root path either.
- **M4, `CaptureTarget::window` takes a borrow** (r1-2-claude#6, r1-3-codex#2, plus r1-3-claude unlogged). Three runs. A guide wording fix is enough.
- **M5, the error-type hierarchy in diagnostics** (r1-3-claude#6, r1-1-codex#3). `DrawError ⊃ RuntimeError`, plus `AppError: From<E> where DrawError: From<E>`, make rustc name `DrawError` in both cases. There are two fixes: an `on_unimplemented` sealed bound, and a documented helper error type for tests that also paint.
- **M6, `CommandId` is `#[must_use]` but is not a guard** (pilot-2-claude#5 aside, warnings in r1-2-claude and r1-2-codex, author notes). An application-lifetime command needs `let _`. Either drop `#[must_use]` from `CommandId` (dropping the id never unregisters; commands.rs:377-380, :511) or keep it and show the binding in the guide.

## Library problems found while verifying (not reported by testers)

- **U1, no import suggestions (observed; cause not established).** rustc does not suggest `use pert_ui::…` for root items that are missing from the prelude. In the probe, with `use pert_ui::prelude::*` in scope, `CommandScope` and `CpuRenderer` got no suggestion, and `Modifiers` got the unrelated `Notifier`. Every facade item is defined in pert-ui-runtime or pert-ui-cpu, which the application does not depend on directly. That is the likely reason, but I have not proved it. This makes every prelude omission cost a documentation search, which strengthens M3.
- **U2, the guide's example warns when copied.** The shortcut example in `guide/diagnostics.md:36-40` writes `ui.register_command(...)?;` and so discards a `#[must_use] CommandId`. Copied into an application, it gives `warning: unused CommandId that must be used` (probe). Doctests do not deny warnings, so the gate does not catch it. Relates to M6.
- **U3, `ApplicationError` cannot wrap a boxed error.** `ApplicationError::new(error: impl Error + Send + Sync + 'static)` (`error.rs:50`) does not accept `Box<dyn Error + Send + Sync>`. Probe: "E0277 the size for values of type `dyn Error + Send + Sync` cannot be known", because `Box<E>: Error` needs `E: Sized`. There is also no `From<Box<dyn Error + Send + Sync>>`. An application whose own functions return the common boxed error can reach `RuntimeError`/`AppError` only through `ApplicationError::from(e.to_string())`, which loses the source chain and `downcast_ref`. Suggest adding `From<Box<dyn Error + Send + Sync>> for ApplicationError` that keeps the box. Destination: TODO.md.
- **U4, prelude rule deviation.** `VirtualList::reorderable` takes `impl FnMut(&mut EventContext, &ListDrop<'_>)` (`virtual_list.rs:970-972`), and its handler matches `DropPosition`. Neither type is in the prelude, against the membership rule "the widgets … with the types their builders take" (lib.rs:302-303). r1-2-claude and pilot-2-claude imported both from the root. Destination: app-author slice 9, with M3.
