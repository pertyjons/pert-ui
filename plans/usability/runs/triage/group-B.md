## Compile diagnostics in this group

- r1-1-claude `diagnostics.md`: "warning: unused `TaskReceipt` that must be used ... note: retain the receipt if the application needs the operation's outcome ... help: use `let _ = ...`". Pointed to the fix and was accurate: the outcome is optional here, because a `Failed` deferred action is also returned from the flush (`tasks.rs:279`).
- `CommandId` warnings (r1-2-claude, r1-2-codex, see table): pointed to `let _ =` but, lacking a reason, misled toward thinking the discard is wrong.
- r1-1-codex#4's "Diagnostic" (`dirty-marker: None`) is the tester's own test-assertion panic, not a compiler message.

## Merged findings

1. **No documented way to start background work from a callback**: r1-1-claude#2 + r1-1-codex acceptance note (own thread + mailbox). Same cause: `Runtime::spawn` is unreachable from `EventContext` except through `defer`, and nothing says so.
2. **Built-in numeric validation is invisible to the application**: r1-1-claude#3 + r1-1-codex#2 + both acceptance notes on "abc". `on_rejection` excludes parse/range failures; `Field` cannot show them; `range` must be repeated in `normalize` to get a message.
3. **Close policy cannot be tested headlessly through `App`**: r1-1-claude#4 + r1-1-codex#6 (the codex run introduced an in-view `FloatingWindow` to get a testable close).
4. **Close admission runs with focused drafts pending**: r1-1-claude author decision. (Corrected in triage: the r1-1-codex in-view close path does save drafts, because its close button takes focus; its native `on_close` calls `clear_focus` first.) Related to 3 (the same close entry points).
5. **Semantic name vs value of static text**: r1-1-codex#4 + r1-4-claude#4 (outside this group; same wording "Presented or edited text").
6. **`#[must_use]` `CommandId`**: author note + r1-2-claude/r1-2-codex diagnostics + pilot-2-claude#5.

## Library problems found while verifying (not reported by any tester)

- **Numeric editors have no `on_modified`** (`text_fields/number_inputs.rs` has none; `TextField`/`TextArea` do, `text_fields.rs:522`, `:768-769`), so a `FormStatus` cannot count unsaved numeric drafts and a close policy cannot see them without clearing focus. Concrete improvement; it would also close part of merged finding 4.
- **Numeric validation messages are fixed English and not in semantics**: `NumberInputError` messages ("enter a representable number", "number is outside the allowed range", `number_inputs.rs:23-31`) are `thiserror` strings, not `UiStrings`, and appear only as the inspection property `validation_error`; an invalid numeric draft's semantics carry `invalid: true` but the description stays the help text (probe 2). `TextField` length refusals, by contrast, are localized (`text_fields.rs:1410-1426`).
- **Close request vs window deactivation commit drafts differently**: deactivation saves valid drafts (`platform/mod.rs:985-991`), a close request does not (`platform/mod.rs:670-672`), so whether a typed value survives a close depends on whether the window lost focus first (e.g. clicking another window before the title-bar close). Part of merged finding 4; worth stating in the TODO entry.
- **`request_close`'s docs do not say how a non-`App` host completes it**; the "Headless hosts consume `take_presentation_requests`" sentence sits only on `request_detach` (`native_windows.rs:1139-1141`), while `take_presentation_requests` says only native hosts need it (`:1186-1187`), which discourages exactly the headless test that r1-1-claude wrote.
